# KN7000 port — platform probes

Read-only MAME probes that measured the KN7000 facts the port relies on. Run against
`kn7000 -bios sp7001` (program 942). A clean PR MAME build needs `-str N`, not
`-skip_gameinfo`, or the autoboot script never starts.

| probe                                                     | question it answers                                                               | result (2026-10-16)                                                                                                                                                                                                         |
|-----------------------------------------------------------|-----------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `heap_probe.lua`                                          | how much the firmware heap (`malloc_X`) can give                                  | ~31 KB free after boot, ~15 KB once the SD screen is open — too small for the game, so game data is loaded into a large RAM window instead                                                                                  |
| `ram_probe.lua`                                           | which large RAM windows an app can write                                          | writable: `0x44000000`, `0x4C000000`, `0x50000000–0x503FFFFF` (work RAM), `0x9CE00000` (LCD, 640×240 RGB565). Not writable: `0x56000000`, `0x96800000`, `0x45000000`, flash `0x48000000`                                    |
| `fileapi.lua`                                             | the framework object's file-method pointers                                       | `framework+0x2E1C` slots `+0x2D0/+0x2D8/+0x2DC` are `fopen_api`/`fread_api`/`fclose_api`                                                                                                                                    |
| `sdread.lua` + `sdread.s`                                 | does reading a file from the SD card work?                                        | **yes** — from the hook, single-backslash path, buffer in work RAM: the exact file bytes appear                                                                                                                             |
| `awpanelmap.lua`                                          | each panel button's bit in the firmware switch-shadow                             | debounced, level-held bitmap: CPR_SEGn at `0x5006BE60+n`, CPL/CPC at `0x5006BE90+n`, bit = `1 << SWn`. See [PANEL-INPUT.md](PANEL-INPUT.md)                                                                                 |
| `awcombo.lua`                                             | (superseded) same-frame combo with per-frame re-press                             | collapses to one bit — but that was test churn, see below                                                                                                                                                                   |
| `awcombo2.lua`, `awstagger.lua`                           | do staggered (human) two-button holds coexist?                                    | **yes** — all four diagonals + move+fire register and persist; only two changes in the *same* 4 ms scan collapse (not reachable by hand)                                                                                    |
| `awdiag.lua`                                              | each button alone vs same-frame pairs                                             | every button registers alone; same-frame pairs collapse (scan-timing artifact)                                                                                                                                              |
| `awinputverify.lua`                                       | do the panel buttons write the right hero variables?                              | all five single-button cases match rustyworld's `update_player` exactly                                                                                                                                                     |
| `awmove.lua`                                              | does holding a direction change the game output?                                  | **yes** — displayed-page checksums diverge by direction (none vs UP vs LEFT)                                                                                                                                                |
| `awnotediff.lua`, `awkeycal.lua`                          | (wrong region) keybed held-note in `0x50148000..`                                 | nothing stable there — only phase caches; superseded by the probes below                                                                                                                                                    |
| `awnodes.lua`, `awnode2.lua`, `awkeyread.lua`             | can a plug-in read held keybed notes?                                             | **yes, polyphonic** — held-slot bitmap `0x500D288C` + note at `0x500D1278+slot*0x2C+0x0C`; 3 notes read at once in-game. See [PLUGIN-INPUT-INTERFACES.md](PLUGIN-INPUT-INTERFACES.md)                                       |
| `awkbdmap.lua`                                            | does the keybed gameplay mapping write the right hero vars?                       | **yes** — F5 left, C6 right, A5 down, Ab5/Bb5 up, C4/bass action; move+fire together, all match the oracle                                                                                                                  |
| `awmiditest.lua` + `gen_held_mid.py`                      | do USB-MIDI-IN notes reach the game's keybed read?                                | **yes** — a SMF on `-midiin1` shows C4/G4/E4 in the TG held mask; a controller drives the game like the keys                                                                                                                |
| `awinput_bug.lua`                                         | why does a key sometimes read as the wrong input?                                 | note-on sets a slot's held bit ~1 frame before its note field, so a fresh slot reads note 0 (action) or a stale note (wrong dir). See GAMEPLAY-BUGFIXES.md                                                                  |
| `awrelease.lua`                                           | how fast does a released key clear?                                               | the sounding mask lags key-up ~50 ms (firmware) -- a released direction lingers ~1 VM frame                                                                                                                                 |
| `awinput_fix3.lua`                                        | does the per-slot 2-frame debounce fix the press glitches?                        | **yes** -- press-context wrong-direction glitch-frames drop to 0                                                                                                                                                            |
| `awdis.py`                                                | what page copies does the water bytecode emit?                                    | `python3 awdis.py resource-0x1b.bin` -> shows COPY src=0x83 (VSCROLL) at 0x01AC = the dynamic-layer carry. Bug-2 evidence                                                                                                   |
| `awcopytrace.lua`                                         | does CopyPage resolve source pages correctly now?                                 | **yes** -- src=0x40->page 0, src=0x03->page 3 (so 0x83->page 3, not page 0)                                                                                                                                                 |
| `awvoices.lua`                                            | does one key sound more than one note (arranger chord)?                           | no -- one key = one voice, correct note (C2..C6 -> 36..84). Rules out harmony/split contamination                                                                                                                           |
| `awalloc.lua`                                             | is a slot's note correct the frame it appears?                                    | **yes** at VM-frame granularity (APPEAR+0 note already right) -- the 'stale note' was sub-frame, never sampled by ReadInput                                                                                                 |
| `awcancel.lua`                                            | diagonals kept, opposing pairs cancelled?                                         | **yes** -- F5+A5 -> left+down (FD=06); F5+C6 and Ab5+A5 -> neutral (switch-lag fix)                                                                                                                                         |
| `awlatency.lua`                                           | how fast does a key press/release reach the mask?                                 | press ~17 ms, release ~50 ms -- the slow release is the 'extra kick' on a direction change                                                                                                                                  |
| `awgone.lua`                                              | is there a faster release signal than the sustain mask?                           | no -- the gone mask 0x500D287C never sets for these voices; release stays ~50 ms                                                                                                                                            |
| `awskipbug.lua`                                           | why did the intro skip with no key?                                               | 0x50149690 is a noisy firmware flag (nonzero with no key); the held mask 0x500D288C stays 0 -> use that                                                                                                                     |
| `awskipok.lua`                                            | intro-skip: no false skip, real key still skips?                                  | **yes** -- 6s no-key stays in intro; C4 -> water in 0.15s                                                                                                                                                                   |
| `awringlat.lua`                                           | is the TG active-voice ring a faster key signal?                                  | **yes** -- ring set 17 ms / release 17 ms (symmetric); sustain mask release 33-50 ms                                                                                                                                        |
| `awring.lua`                                              | is the ring polyphonic/per-note?                                                  | **yes** -- C4+G4 -> {60,67}; release C4 -> {67} within a frame                                                                                                                                                              |
| `awstray.lua`                                             | does walking the ring cut the extra kick?                                         | **yes, ~halved** -- wrong-direction frames sustain=23/99 vs ring=13/99 (clean A/B)                                                                                                                                          |
| `awmidiq.lua` + `gen_q_mid.py`, `awmidiqtrace.lua`        | where do note events land in RAM, for MIDI IN and the keybed?                     | firmware byte rings: MIDI IN 1 bytes in the ring at `0x5001F060`; every keybed note as MIDI in the MIDI OUT 1 TX ring `0x5001F874` (and `0x5002049C`). The module reads these. See [INPUT-PRECISION.md](INPUT-PRECISION.md) |
| `awkeystate.lua` + `keystate_find.py`, `gen_q2_mid.py`    | is there a per-note held-key table in work RAM?                                   | no -- only TG voice-node bits and the voice held mask track notes                                                                                                                                                           |
| `awkbreplay.lua`, `events_to_mid.py`, `raw_vs_applied.py` | does the VM apply the canonical input for a re-performed session (keybed / MIDI)? | voice-ring build: 59 / 62 wrong ticks; MIDI-ring build: **0 / 0** of 717 (fixture `sessions/2026-10-17-fsanches-misinput1-*`)                                                                                               |
| `awricost.lua`                                            | how many instructions does one ReadInput execute?                                 | voice-ring build 127; MIDI-ring build 805 (~+21 us per ~80 ms frame at 32 MHz, ~0.03 %); frame pace unchanged                                                                                                               |

Work RAM `0x50000000–0x503FFFFF` is definitely real and the firmware uses it heavily; the
library at `0x4C000000` runs from RAM, so the CPU fetches instructions from RAM — the VM can
be loaded from the SD card and executed. `0x44000000` is mapped as 16 MB of RAM by the MAME
driver; its real-hardware size is not yet confirmed, so a real-instrument build must verify it.
